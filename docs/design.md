## 目标与范围

替代 NAS 上游 pdf2zh-next 2.9.0 / BabelDOC 0.6.2 的完整翻译应用和编排逻辑。交付不包含 CPython、Gradio、BabelDOC Python 包，也不通过 PyO3 嵌入或子进程调用旧 Python 引擎。允许复用成熟 C/C++ PDF、字体和模型推理库，以及经校验的模型、字体数据。

已有 translator 项目与已运行的 NAS 原版服务不迁移、不覆盖。Mac 仅保存本设计与交接；源码、依赖、模型、构建和镜像在 NAS 独立目录 `/vol1/1000/docker/pdf2zh-rust/` 中处理。该路径为拟定工作目录，实施前检查是否已存在及其指令，禁止覆盖已有用户文件。

用户选择解决的是“无任务时仍驻留约 334 MiB”的问题；翻译时模型、PDF 和页面图像的真实内存仍需要保留。完整重写是一条分阶段交付路径，不能以网页启动或单页演示代替功能完成。

## 已核查基线

现场版本及 import RSS 见 findings.md。容器空载 docker stats 约 334.4 MiB，不将其与单进程 RSS 混为同一口径。

NAS 上安装文件的静态统计：pdf2zh_next 35 个 Python 文件、10410 行；BabelDOC 190 个 Python 文件、75257 行，包含数据、配置和辅助代码，不能把这些行数当成必需移植的算法行数。BabelDOC 的 PDF 流程涉及解析、布局、段落、公式/样式、翻译、重排、字体、输出合并；完整等价需逐项验证。

## 库的边界

| 现有层 | 新实现 | 验证重点 |
| --- | --- | --- |
| PyMuPDF | Rust MuPDF 绑定，必要时增加局部 C ABI 适配层 | 字符/字体信息、旋转/裁剪、内容流访问、向量及图片保留、输出文字可搜索 |
| ONNX Runtime Python 包 | `ort` Rust 绑定调用原生 CPU runtime | 现有版面模型的输入预处理、张量布局、输出解码、NMS 一致性 |
| NumPy / 图像预处理 | Rust 连续缓冲区和图像操作；确有必要时才引入 OpenCV 原生接口 | 像素尺寸、归一化及颜色顺序的数值一致性，避免重复复制整页图像 |
| BabelDOC 解析与排版 Python 代码 | Rust 中间表示和处理流程 | 阅读顺序、段落、公式、字体选择、译文溢出与断行 |
| Python 翻译服务 SDK | Rust HTTP 客户端和各服务商适配器 | 鉴权、限流、重试、响应解析、取消、缓存 |
| Gradio | Rust HTTP 服务＋独立静态网页 | 上传、选项、进度、取消、预览和下载；视觉另行设计，不改现有 translator 前端 |
| 缓存及任务存储 | SQLite | 有界历史和翻译缓存；缓存键含文本、语言、服务商、模型、提示词和术语库版本 |

成熟库有对应能力不代表 Rust 封装已覆盖 PyMuPDF 全部高级接口。先验证所需 API 的实际可用性；缺口在独立适配模块中补足，禁止把缺失功能静默降级为整页栅格图片。

## 运行结构与内存生命周期

单个 Rust 可执行文件提供 `serve`、`translate` 和内部 `worker` 模式。

1. `serve` 常驻，只处理 HTTP、配置、任务队列、SQLite 和静态资源；不创建 PDF 文档、加载模型或预热字体。
2. 任务入队后，由服务启动同一程序的独立 `worker` 进程。默认一次只执行一个文档，翻译请求并发受独立限流器约束。
3. worker 打开输入文件，按页/有界分块处理，重型 PDF、图像和模型状态仅留在 worker。跨页段落采用明确的有界上下文窗口或磁盘中间结果，不把整本的所有位图放进内存。
4. 子进程通过有上限的逐行 JSON 消息报告阶段、页数和错误；服务持久化并通过 SSE 输出。不能把 API Key 放进进程参数、事件、日志或结果元数据。
5. 成功时，校验结果后将临时文件原子转为正式输出；失败只保留明确的诊断记录，不出现伪完成文件。
6. 取消先发出协作信号；超过宽限时间终止本任务 worker 并回收。服务重启时将遗留运行任务标记为 interrupted，不虚报成功。
7. 每个任务结束后 worker 退出，回收本次 PDF 库、模型和分配器资源。下次任务承担重新加载的启动延迟。

容器启动不主动下载大型资源。资源由显式准备命令按版本和 SHA-256 校验后写入 NAS 持久卷；缺失时告知缺少的资源和准备方法。资源、缓存、输入和输出目录分开。

## PDF 核心处理链

1. 验证输入、密码和页范围；读取页面变换、裁剪框、文字、字体、图形、图片、链接与目录等结构。
2. 按需渲染当前页以执行布局模型，建立文本块、表格、图片和公式区域。保存原 PDF 对象到中间表示的关联，不依赖“提取纯文本后重新生成整页”。
3. 推断阅读顺序，合并行、连字符和跨栏/跨页段落；识别保护区域及行内公式，保持可逆的占位关联和样式片段。
4. 对可翻译段落执行术语替换和翻译请求；校验返回的保护标记、数量与结构。校验失败时重试或报错，不能悄悄丢公式。
5. 用原版面约束排版译文，测量字体和字形宽度、换行、回退与字号。明确报告无法容纳的段落，不以裁掉文字隐藏溢出。
6. 修改可翻译内容并保留保护对象、图片和向量图；输出单语、双语交替页和并排版本，写入正确的字形编码、可搜索文字与可迁移的目录/链接。
7. 重开结果做结构检查，并对代表样本渲染对照。不是仅检查文件存在。

扫描页检测、已有 OCR 层、异常字体、旋转文字、表格和加密文档单独列入覆盖项。上游参数如含 OCR workaround，必须先核实实际语义，不把检测扫描页等同于已实现完整 OCR。

## 分阶段交付与功能对照

| 阶段 | 可验收产物 | 不代表什么 |
| --- | --- | --- |
| P0 核心技术验证 | NAS 可构建的 Rust CLI；读写真实 PDF，提取字符几何及字体；保留公式/向量；写入可搜索中文；原生模型独立推理 | 不是完整译文排版或完整替代品 |
| P1 翻译引擎 | 单/双栏论文、行内/独立公式保护、真实翻译、字体回退、溢出检测、三种导出 | 未完成的边界样本和服务商必须列明 |
| P2 应用与兼容 | 配置、术语库、缓存、任务/取消/历史、CLI、静态 WebUI、原版 GUI/CLI 功能与配置项逐项对照 | 不能只支持一个接口就宣称全部服务商兼容 |
| P3 NAS 交付 | 独立 Docker 镜像和持久卷、重启/失败恢复、资源准备、质量及内存报告 | 不自动替换现有原版服务 |

P0 先验证“字符与原内容对象的关联、保护公式、替换正文、正确输出中文”这一高风险链路。若现有绑定无法满足，先补适配或重新评估 PDF 后端，不先大量建设外围页面。

翻译服务先实现通用兼容接口以跑通链路；完整交付前仍需根据 NAS 固定版本的配置与 translator 实现建立逐项对照表，覆盖其他 SDK 专有服务商。无测试凭证的适配器只能注明已实现/契约验证，不能标记真实联调通过。凭证需求只在确实阻塞具体服务商联调时向用户提出，不重复索取已有配置。

## 验收与测量

- 功能：固定同一组有权使用的测试 PDF，包括单栏、双栏、行内和独立公式、表格、混合字体、旋转页面、长文档及扫描/受限输入；比较页数、几何、保护公式/图形、可搜索文字、阅读顺序、断行、漏译与溢出，保存失败样例。
- 真实翻译：同一输入、语言、服务商、模型、术语库及主要参数对照原版；原版结果也是对照而非自动真值。没有凭证或离线时分别标注结构测试和真实翻译测试。
- 内存：同 NAS、同 cgroup 指标记录原版与新服务的启动空闲、首个任务峰值、任务后 2 分钟、重复任务后的空闲；同时报告进程 RSS，不能将二者直接相减。
- 目标：常驻服务空闲 cgroup 内存争取不超过 50 MiB，这是待验证目标；模型和 PDF worker 不得空闲常驻。翻译峰值另测，不承诺同比降低。
- 生命周期：成功、超时、API 失败、取消、worker 崩溃和容器重启后，都不得遗留持续运行的任务进程或伪完成文件。完成多次任务后检查子进程和常驻内存是否回落。
- 构建：固定 Cargo.lock、MuPDF/runtime/模型/字体版本和摘要，记录完整依赖与许可证。需要 NAS 上实际构建和运行结果后才能宣称可部署。
