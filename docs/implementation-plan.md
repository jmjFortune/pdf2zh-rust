# NAS Rust 重写实施步骤

设计已于 2026-10-22 获用户“OK”批准。实现留在 NAS 独立仓库，不修改 translator 业务代码。

1. 环境与版本控制：检查 NAS 目录和父目录指令，建立独立 Git 分支、工具链目录及持久日志；Rust/Cargo 依赖只下载到 NAS。限制构建并发，不修改系统 Python 或运行中的原版容器。
2. PDF 技术验证：选定并锁定 MuPDF Rust 绑定，构建 CLI。用自建、无用户隐私的 PDF 样本验证字符几何、字体、文字替换、向量和中文可搜索输出；如绑定有缺口，在本项目适配层解决。
3. 布局与保护：复用经校验的版面模型和原生 ONNX Runtime，实现图像预处理与后处理，验证实际推理；建立几何、样式和公式保护的中间表示，以及阅读顺序/段落合并。
4. 翻译与重排：实现限流、重试、术语库、翻译缓存及服务商适配；校验保护标记；完成字体度量、断行、溢出报告和单语/双语两种布局导出。
5. 应用：Rust serve/worker 分离，SQLite 持久化队列、状态和缓存，SSE 进度、取消、重启恢复、历史与输出下载；静态界面独立于 translator 前端。
6. 部署：构建无 Python 运行时的独立镜像，映射独立端口与持久卷；原版继续运行，作为对照。
7. 验证：Rust 单元/集成测试、真实 PDF 重开及渲染、真实翻译、取消/失败/重启恢复、容器内存和依赖检查。逐项记录上游能力覆盖；未验证或未完成的功能不标记完成。

现有现场：NAS x86_64，vol1 可用约 451 GiB，内存 available 约 4.3 GiB；有 cc/make/git/curl，无 PATH 中 rustc/cargo。`writing-plans` 技能未安装，已搜索两个技能根和插件目录；使用本可执行步骤文件作为替代，不因此停止用户已批准的实施。
