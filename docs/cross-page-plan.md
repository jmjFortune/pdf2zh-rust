# 跨页联合翻译修复

本次为当前 Rust 引擎补齐相邻页边界正文的 LLM 联合输入，保留每段的原页、坐标与公式对象。

## 1. 已批准的方案

用户在同输入 Python/Rust A/B 确认差异后回复“那就修复吧”，按此前解释的“同批输入、独立 ID 回填”执行。全文重新分页与直接拼接中文再按字数切分不在范围内。原 translator 业务代码、表格策略与 Downloads/extend 保持不变。

现有独立仓库 agent/codex/rust-engine 仅有原先未跟踪的 .DS_Store，复用这个专用 agent checkout；不创建额外工作区。brainstorming 所需方案已在前文展示并由本次指令批准，无需重复请求许可。当前可用技能目录未列出 writing-plans，使用本文件记录实施与验收。

## 2. 数据流与边界

- 只为 OpenAI-compatible、Azure OpenAI 和 Ollama 原生 LLM 路径启用，其他服务保持逐段处理。
- 版面分析启用时，取连续且均被选择的两页中末个/首个合格正文单元；标题、表格、公式区、代码、页眉页脚与空白页不补成正文。
- 必要时只预分析下一页，保留“先验证第一页供应商，再分析全文”的既有流程；分析子进程仍在 HTTP 请求前退出。
- 两段作为 JSON 数组输入，保留 ID 0/1；提示词明确片段可能属于同一段，但不得跨 ID 移动译文或公式标记。
- 每个输出单独校验 ID、非空、大小及公式标记；保留下一页首段的译文，后续写回原位置且不重复调用。
- 联合缓存键包含完整有序输入对、语言、服务、模型、术语与选项，不能命中旧孤立段落缓存。非法 JSON/ID/公式输出按段回退；永久供应商 HTTP 错误继续失败，不通过回退重复请求。
- 离线 cache-only 恢复不新增请求；没有联合缓存时可沿用既有逐段缓存恢复，明确这不包含新增跨页语义能力。

## 4. 验收

- 修复前新回归必须失败，修复后跨页两段在一个真实 HTTP 请求体中，各自 ID 回填原页且不重复翻译。
- 覆盖相同编号公式分属两个 ID、无效响应回退、上下文改变不复用缓存、同输入缓存复用、跳页不配对及离线无网络。
- 既有 PDF、旋转裁剪、公式、代码、任务取消/重启与 provider 契约测试保持通过。
- 不使用用户 Key，不自动重译旧任务，不部署或修改 NAS。后续如需发布部署，另按现有镜像/空闲检查流程执行。

## 5. 风险与限制

本次补请求组织差异，不保证目标模型对所有断句必然改善。三页以上同一段连续延伸、跨栏重建和完整上游语义覆盖不在本次范围。小幅下一页预取会改变边界处进度节奏，不增加长期驻留模型。
